What you are looking at

This page arrived over HTTP/2 from a server that does not import net/http. The connection preface, the SETTINGS exchange, the HEADERS and DATA frames and the HPACK compression of every field below were all written from scratch against RFC 9113 and RFC 7541.

Do not take that on trust. Everything on this page is read out of your own browser's Resource Timing entries, which your browser fills in from its own network stack and not from anything the server can claim.

System design — one directory, one way down

Each box is one Go package. Arrows are imports, and they only point down: the frame layer has never heard of a request.

Control architecture — who is allowed to write

One connection, three kinds of goroutine. Only one of them ever touches the socket's write half; everyone else hands it a frame and walks away. That is what keeps a multiplexed frame stream from interleaving into nonsense.

Data flow — one request, end to end

Follow the dot: this is a GET for a file, from the first octet the kernel hands us to the DATA frames going back out.

Live — watch the streams multiplex

HTTP/1.1 needs one connection per request in flight; a browser opens six to one host and queues the rest. HTTP/2 interleaves them all on one. The button below asks for 64 resources at once, on the single connection this page arrived on, and draws each one as it lands.
